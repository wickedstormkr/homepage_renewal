# 인스타그램·블로그 운영과 홈페이지 연계 가이드

2026-09-25 작성. 홈페이지 개편(브랜치 `feat/2026-09-site-refresh`)과 함께 만든 운영 기준입니다.

## 1. 세 채널의 역할

| 채널 | 역할 | 올리는 것 | 끝에 붙이는 링크 |
|---|---|---|---|
| **홈페이지 소식** (`news/<id>.html`) | 정본. 기사 원문, 자료, 문의가 모이는 곳 | 보도자료형 기사, 특허·인증, 사업 소식, 기술 노트 | 자료실(`#resources`), 문의(`#contact`) |
| **블로그** (네이버 블로그 권장) | 검색 유입. 긴 설명과 사례 | 기사를 풀어 쓴 해설, 표준 쉬운 설명(xAPI·1EdTech CASE), 제품 사용 흐름 | 홈페이지 기사 원문 |
| **인스타그램** | 현장감과 인지도. 짧고 시각적으로 | 행사 현장 사진, 카드뉴스 3~5장, 제품 화면 15초 릴스, 기업 영상 컷 | 프로필 링크 = `links.html` |

원칙은 **홈페이지에 먼저 올리고, 블로그와 인스타그램은 그 기사로 사람을 데려오는 것**입니다. 기사 주소가 하나로 모여야 검색·공유·분석이 쌓입니다.

## 2. 소식 하나를 세 채널에 내는 순서

1. **홈페이지 기사**: `data/posts.json`에 글을 넣고 `node scripts/generate-news.mjs` 실행 → `news/<id>.html` 생성. 메인 '최근 소식'에 보이려면 `"pinned": true`(최근 3건만 노출).
2. **블로그**: 같은 날, 기사를 해설형으로 풀어 쓰고 마지막 문단에 원문 링크.
3. **인스타그램**: 사진 1장 + 카드뉴스 3~5장. 본문 첫 줄에 핵심 한 문장, 끝에 "자세한 기사는 프로필 링크에서". 프로필 링크(`links.html`)의 첫 버튼은 최신 기사로 **자동으로 바뀝니다**.

## 3. 링크에 붙이는 표시(UTM)

GA4(G-0Y5QD1HBGN)에서 채널별 유입을 나눠 보려면 링크 끝에 아래를 붙입니다.

| 어디서 | 붙이는 값 |
|---|---|
| 인스타그램 프로필 | `links.html`에 이미 들어 있음 (`utm_source=instagram&utm_medium=social&utm_campaign=bio`) |
| 인스타그램 스토리·게시물 | `?utm_source=instagram&utm_medium=social&utm_campaign=<기사 id>` |
| 블로그 본문 | `?utm_source=blog&utm_medium=referral&utm_campaign=<기사 id>` |
| 박람회 QR·인쇄물 | `?utm_source=fair&utm_medium=print&utm_campaign=<행사명>` |

`utm_source`가 `instagram`·`blog`·`fair`이면 문의 폼의 '유입 경로'가 인스타그램·블로그·박람회·행사로 **미리 선택**됩니다(방문자가 바꿀 수 있음). 서버에는 기존 값 목록을 늘리지 않도록 `etc` + 채널 이름으로 들어갑니다.

## 4. 계정을 만든 뒤 홈페이지에 연결하기

1. `js/site-config.js`의 `SOCIAL`에 주소와 표시 이름을 넣습니다.
   ```js
   SOCIAL: {
     instagram: { url: "https://www.instagram.com/<계정>/", label: "@<계정>" },
     blog: { url: "https://blog.naver.com/<아이디>", label: "위키드스톰 블로그" }
   }
   ```
   넣는 순간 메인 '최근 소식' 아래 채널 띠와 모든 페이지 푸터에 링크가 나타납니다. 비워 두면 숨겨집니다.
2. `index.html` JSON-LD의 `"sameAs":[]`에 같은 주소를 넣습니다(검색엔진이 공식 채널로 인식).
3. 인스타그램 프로필 링크에 `https://wickedstorm.kr/links.html`을 넣습니다.

## 5. 지금 있는 자산으로 만든 첫 4주 게시 계획

| 주 | 인스타그램 | 블로그 | 쓰는 자산 |
|---|---|---|---|
| 1 | 코엑스 부스 현장 사진 + 카드뉴스 "학습의 선순환 5단계" | 박람회 참가 기사 해설 | `img/news/`, `img/learning-loop-ko.webp`, 슬랙 현장 사진 |
| 2 | 기업 홍보 영상 15초 컷(릴스) | "국제 표준 학습데이터란" (xAPI·1EdTech CASE 쉬운 설명) | `media/company-film.mp4` |
| 3 | 하노이 VIETEDU 2026 참가 예고(10.15~18) | LearnHubble AI 학습자 화면 둘러보기 | 영문 배너, `img/lh-*.webp` |
| 4 | 하노이 현장 사진 | 하노이 참가 기사(홈페이지 기사 먼저) | 현장 사진 |

주 1~2회가 무리 없는 속도입니다. 현장 사진은 행사 당일 인스타그램 스토리로 먼저 올리고, 기사는 행사 후 1주 안에 홈페이지 → 블로그 순으로 냅니다.

## 6. 표기 규칙 (홍보물 정본과 동일)

- 제품명은 **Lecognizer / LearnHubble AI**. Lecognizer AI는 Lecognizer의 AI 기능 이름으로만. GROWA·LXP·EventStore를 제품명처럼 쓰지 않습니다.
- 주체는 **운영자·교수자·학습자**. "기록"보다 **학습데이터**.
- AI는 **찾고·분석하고·제안하고·초안을 만들고·힌트를 건넵니다. 판단·확인·적용은 사람**이 합니다.
- 쓸 수 있는 수치: GS 인증 1등급, AI 특허 2건 등록(제10-2883249호·제10-2767110호), 똑똑! 수학탐험대 누적 사용자 240만 명(사업명과 함께).
- 쓰지 않는 것: BMT·성능 평가 순위, 수상으로 확정되지 않은 출품 이력, 임직원 수·비율, **화면 속 시연용 숫자**(47%→75% 등)를 성과처럼 뽑아 쓰는 것.
- 1EdTech 표기: "1EdTech Korea 설립 이사회 참여사 · 1EdTech Contributing Member".
- 문장 부호: 긴 줄표(—)를 쓰지 않습니다. 쉼표·가운뎃점(·)·콜론으로 대신합니다.
- 사진 속 방문객 얼굴이 정면으로 크게 나온 사진은 동의 없이 쓰지 않습니다.
